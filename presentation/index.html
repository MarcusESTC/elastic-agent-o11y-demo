The Problem

AI Agents Are Black Boxes

❓ No Visibility

You know the user sent a message and got a reply. Everything in between — model calls, latency, token usage, errors — is invisible.

💸 Cost Blindness

Token costs accumulate silently. No per-request breakdown, no alerting on spend spikes, no user-level attribution across sessions.

🔧 Black Box Tools

Agents call tools (search, calculate, APIs) on your behalf — but you can't see which tools fired, in what order, or how long each one took.

📊 No SLOs

You can't set latency or error-rate SLOs on something you can't measure. Customers feel the pain before you do.

A/B Model Routing

Per-Session
Model Assignment

At session start, each user is permanently assigned to a model variant for their entire session. The ab.variant attribute is stamped on every span and metric — so you can split any KPI by model in Kibana with a single filter.

70%
gemini-2.5-flash
control — full capability
30%
gemini-2.5-flash-lite
treatment — cost / speed

Split any dashboard panel by ab.variant to compare P95 latency, token cost, error rate, or feedback score between models in real time.

Session assignment logic

def assign_ab_variant(session_id: str) -> str:
    # Deterministic hash — same session = same model
    h = int(hashlib.md5(
        session_id.encode()).hexdigest(), 16)
    if (h % 100) < 70:
        return "control"   # gemini-2.5-flash
    return "treatment"  # gemini-2.5-flash-lite

# Stamp on every span in this request
span.set_attribute("ab.variant", variant)
span.set_attribute("gen_ai.request.model", model)

ES|QL — compare models

FROM traces-generic.otel-default
WHERE attributes.gen_ai.operation.name
      == "invoke_agent"
STATS avg_dur = AVG(duration),
      p95_dur = PERCENTILE(duration, 95)
BY attributes.ab.variant
Guardrails & Safety

PII Detection
Before the LLM

Before every LLM call, a regex guard scans the user message for PII. If a match is found, the content is redacted, a span event is recorded, and a metric counter is incremented. The LLM never sees raw PII.

Detected patterns:

email phone SSN xxx-xx-xxxx credit card
  • Span event guardrail.pii_detected on the active span
  • Metric gen_ai.guardrail.violations counter incremented
  • Redacted message sent to LLM — no data leakage
  • Alert rule fires if violations spike > 10/min

Span event payload

{
  "name": "guardrail.pii_detected",
  "timestamp": 1724500812345678,
  "attributes": {
    "guardrail.type": "pii",
    "guardrail.pattern": "email",
    "guardrail.action": "redacted",
    "guardrail.match_count": 1,
    "session.id": "ses_a3f9...",
    "ab.variant": "control"
  }
}

Metric instrument

guardrail_violations = meter.create_counter(
    "gen_ai.guardrail.violations",
    unit="{violation}",
    description="PII or policy violations caught"
)

# On detection:
guardrail_violations.add(1, {
    "guardrail.type": "pii",
    "guardrail.pattern": pattern_name
})
